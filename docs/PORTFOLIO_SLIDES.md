## ② 배경 / 문제

**배경**
- 사내 Confluence 문서 **640건**을 수집했고, 이 중 본문이 있는 **583건 / 3,211청크**를 색인했습니다.
  나머지 **57건(9%)은 본문이 비어 있었습니다.**
- 계층이 깊어 키워드 검색만으로는 근거를 찾기 어려웠습니다.
- 답변 모델만 연결하면 출처 없는 추측이 섞여 업무에 쓰기 어려웠습니다.

**결론**
→ 그래서 키워드 검색과 의미 검색을 결합하고, 답변마다 Confluence 원문 링크를 붙이기로 했습니다.

**문제 정의**
LLM은 검색해 온 문서만 보고 답합니다. **검색이 답변 품질의 상한선입니다.**
그런데 키워드 검색은 단어가 겹치면 뜻이 달라도 상위로 올리고, 의미 검색은 뜻은 맞지만 점수 폭이 좁아 순위를 믿기 어렵습니다.

**근거 자료 — 같은 질문, 세 가지 검색 (2026-09-14 실측)**

임직원이 던진 질문: **"3년 동안 일한 사람은 며칠 동안 쉴 수 있어?"**

이 답이 실려 있는 문서: **`3년 근속 주기 Refresh 휴가 제도`** (아래 표에서 ✅)

먼저 짚을 것은, **질문과 정답 문서가 쓰는 단어가 거의 다르다**는 점입니다.

| | 형태소 분석 결과 |
|---|---|
| 질문 | `3` `년` `동안` `일` `사람` `며칠` `동안` `쉴` `쉬` `수` `있` |
| 정답 문서 제목 | `3` `년` `근속` `주기` `refresh` `휴가` `제도` |
| **겹치는 것** | **`3`, `년` — 두 개뿐. 그것도 문서 대부분에 나오는 흔한 말입니다.** |

직원은 "일한", "쉴"이라고 물었지만 문서는 "근속", "휴가"라고 씁니다.
**키워드 검색이 구조적으로 불리한 조건입니다.**

| 순위 | BM25 단독 (키워드) | kNN 단독 (의미) | 하이브리드 (RRF) |
|---|---|---|---|
| 1 | ❌ 주간 업무 보고서 3/23~3/27 `20.71` | ✅ **3년 근속 Refresh 휴가 제도** `0.744` | ✅ **3년 근속 Refresh 휴가 제도** `0.03048` |
| 2 | ✅ **3년 근속 Refresh 휴가 제도** `20.19` | ❌ (협업 툴) Flex HR `0.682` | ❌ 2026 Q2 피드백 `0.02499` |
| 3 | ❌ talk-stock 2026-07 `18.98` | ❌ AI 풀스택 개발자 (8년 이상) `0.680` | ❌ 중소기업 청년소득세 감면 `0.02176` |
| 4 | ❌ 2026 Q2 피드백 `18.61` | ❌ 20260420_리더주간미팅 `0.673` | ❌ 건강검진(필수) `0.02175` |
| 5 | ❌ 회사 연차 규정이 궁금해요! `18.57` | ❌ 2026-04-10 2주차 정기 미팅 `0.671` | ❌ 주간 업무 보고서 3/23~3/27 `0.01770` |
| | 1위와 5위의 차 **2.14** | 1위와 5위의 차 **0.073** | 1위와 5위의 차 **0.01278** |

**하이브리드 1위 점수가 어떻게 나왔나** — RRF는 점수를 안 보고 **등수만** 봅니다.
각 리스트에서 `1/(60 + 등수)`를 받아 더합니다.

| 문서 | BM25 등수 → 기여 | kNN 등수 → 기여 | 합계 |
|---|---|---|---|
| ✅ 3년 근속 Refresh 휴가 제도 | 11위 → `1/71` = 0.01408 | **1위** → `1/61` = 0.01639 | **0.03048** |
| ❌ 주간 업무 보고서 | **1위** → `1/61` = 0.01639 | 후보 밖 → 0 | 0.01639 |

양쪽에 든 문서는 두 번 더해지므로, **BM25 1등이지만 kNN 후보에 없는 문서보다 위로** 옵니다.

**BM25 단독 — 정답을 찾긴 했지만 1위를 뺏겼습니다.**
1위로 올라온 것은 주간 업무 보고서입니다. "3년", "동안" 같은 흔한 말이 많이 등장하기 때문입니다.
정답은 2위(20.19)로, 1위(20.71)와 **0.52밖에 차이가 나지 않습니다.**
게다가 1위부터 5위까지의 점수 차가 2.14뿐입니다. 다섯 건이 사실상 동점이라는 뜻이고,
**키워드 검색 스스로도 어느 것이 맞는지 모르고 있다**는 신호입니다.

**kNN 단독 — 단어가 겹치지 않는데도 정답을 1위로 올렸습니다.**
"일한 사람이 쉬는 것"과 "근속 휴가 제도"가 같은 뜻이라는 것을 벡터가 알아봤습니다.
이것이 의미 검색을 넣은 이유입니다.
다만 1위 0.744, 5위 0.671로 **점수 차가 0.073밖에 안 됩니다.**
정답과 무관한 "AI 풀스택 개발자 채용 공고"가 거의 같은 점수를 받았습니다.
이번에는 맞았지만 이 정도 차이로는 다음에도 맞을 거라고 기대하기 어렵습니다.

**하이브리드 — 정답이 1위이고, BM25 1등이었던 오답은 5위로 내려갑니다.**
1위 0.03048, 2위 0.02499 (2위의 **1.22배**).
양쪽 검색이 모두 상위로 올린 문서가 두 번 더해지는 구조라, 한쪽만 좋아한 문서는 내려갑니다.
**"정답이 1위"인 것보다 "1위가 확실히 1위"인 것이 중요합니다.**
순위를 믿을 수 있어야 상위 5건만 잘라 LLM에 넘길 수 있기 때문입니다.

## ③ 해결 과정

**1. 수집·색인 파이프라인**
- Confluence 페이지네이션으로 640건을 수집하고, updated_at을 비교해 바뀐 문서만 다시 임베딩합니다.
- 왜 증분으로 했나: 재색인 비용의 대부분이 임베딩 API 호출이라, 전체 재색인은 문서가 늘수록 감당하기 어렵습니다.
- 문서가 짧아져 남는 고아 청크를 정리하고, 별칭 전환으로 재색인 중에도 검색이 끊기지 않게 했습니다.

**2. 검색과 생성 설계**
- BM25와 kNN을 따로 실행한 뒤 **각 리스트에서의 순위로 결합(RRF)**합니다.
  raw score를 그냥 더하면 BM25(수십 단위)가 kNN(0~1)을 압도해 사실상 BM25 단독이 됩니다.
  처음에는 각 리스트를 0~1로 정규화해 가중평균했으나, 폭이 좁은 kNN 리스트의 미세한 차이가
  부풀려지는 문제가 있어 **순위 기반 표준 방식(RRF)으로 바꿨습니다.**
- 후보 풀을 50으로 넓히고, 청크가 아니라 **서로 다른 문서** 5건을 고른 뒤 각 문서의 전문을 이어붙입니다.
  같은 문서의 청크가 상위권을 독점하면 정작 답이 있는 부분이 컨텍스트에서 빠집니다.
- 12자 미만의 짧은 질문과 1,000자 이상의 긴 맥락은 gpt-4o로, 나머지는 deepseek-chat으로 보냅니다.

**3. 평가 체계 — 그리고 평가셋을 의심한 것**
- 45문항 골든셋에 검색 지표 2개, 자체 생성 지표 2개, RAGAS 표준 지표 2개를 함께 기록합니다.
- 세 점수를 조합하면 오답 원인을 검색 실패 / 컨텍스트 무시 / 이해 실패로 분리할 수 있습니다.
- **그 평가셋이 한쪽으로 기울어 있다는 것을 발견했습니다.** 질문 생성 프롬프트가 "문서를 식별할 수 있는
  키워드를 반드시 포함하라"고 지시한 탓에, 채점 문항 38개 중 27개(71%)가 정답 문서의 제목 단어를
  그대로 담고 있었습니다(평균 84.7%). 키워드 검색에 절대적으로 유리한 조건입니다.
- 같은 정답 문서를 겨냥하되 제목 단어를 뺀 **대조 평가셋**을 만들어(누출률 6.4%) 다시 측정했습니다.

**4. 백엔드 구성과 관측**
- 컨테이너마다 메모리 상한을 두고, Compose를 4개 계층으로 나눠 모니터링을 빼도 서비스가 도는 구조로 했습니다.
- Spring Boot 백엔드는 계층 분리, 생성자 주입, DTO 매핑, 읽기 전용 트랜잭션 구분 등 MVC 관례에 맞춰 구성했습니다.
- Prometheus·Grafana로 backend → ai-server → LLM → Elasticsearch 계층별 p95를 한 그래프에 겹쳐,
  지연이 어느 계층에서 생기는지 바로 가릅니다.

## ④ 결과 / 성과

**검색 지표** (2026-09-14 재측정 / 583문서 · 3,211청크 / 채점 38문항)

| 지표 | 값 | 의미 |
|---|---|---|
| retrieval_hit@5 | **0.974** | 정답 문서가 상위 5건 안에 든 비율 |
| retrieval_mrr | **0.908** | 정답 문서의 평균 순위 역수 (1~2위) |

**생성 지표** (2026-09-14 재측정 / 45문항 / 판정 모델 solar / **채점 누락 0건**)

| 지표 | 값 | 의미 |
|---|---|---|
| answer_correctness | **0.958** | 기대 답변과의 일치 |
| answer_faithfulness (자체) | **0.973** | 답변이 검색된 근거에만 기대는가 |
| ragas_faithfulness (표준) | **0.856** | 위와 같은 것을 표준 구현으로 |
| ragas_context_precision | **0.851** | 검색된 문서 중 실제로 답변에 쓰인 비율 |

> **여섯 지표가 모두 45문항 온전히 채점된 첫 실행입니다.**
> `ragas_context_precision`은 검색 방식을 RRF로 바꾸면서 0.753 → **0.851**로 올랐습니다.
> 가져온 문서의 쓸모가 좋아진 것인데, `hit@5`·`MRR`로는 드러나지 않는 개선입니다.

**하이브리드가 실제로 한 일 — 편향을 제거하고 재측정**

| 방식 | 제목 단어 있는 질문 | 제목 단어 없는 질문 | 낙폭 |
|---|---|---|---|
| BM25 단독 | MRR 0.864 | MRR 0.390 | **−55%** |
| **하이브리드 (RRF)** | MRR **0.908** | MRR **0.560** | **−38%** |
| kNN 단독 | MRR 0.812 | MRR 0.501 | −38% |

hit@5로 봐도 같은 방향입니다. 제목 단어가 없을 때 BM25 0.605 / 하이브리드 **0.763**.

문항별 직접 대결(하이브리드 vs BM25): 제목 단어가 있을 때 5승 3패, **없을 때 16승 2패**.

→ **하이브리드의 값어치는 평균 성능이 아니라 최악의 경우 방어에 있습니다.**
BM25는 질문에 문서 제목 단어가 있으면 강하지만, 없으면 절반 아래로 떨어집니다(−55%).
하이브리드는 같은 조건에서 −38%로 덜 무너집니다.
질문 표현을 통제할 수 없는 사내 챗봇에서는 이 성질이 최고점보다 중요합니다.

**실제 활용**
사내 AX 과제로 구성했습니다. 임직원이 Confluence 문서를 대화로 찾고, 답변에 붙은 출처 링크로 원문을 바로 확인할 수 있습니다.

**배운 것**
- **측정 도구를 먼저 의심해야 했습니다.** 제가 만든 평가셋이 제가 만든 기능에 불리하게(그리고
  다른 방식에 유리하게) 기울어 있었고, 그것을 모른 채로는 개선을 증명할 수 없었습니다.
- **자체 지표만 보면 편향을 알 수 없었습니다.** 표준 지표를 나란히 두자 자체 faithfulness가
  RAGAS보다 0.113 후하게 채점한다는 점이 드러났습니다. 답변 전체를 한 번에 판정하는 방식이 원인이었습니다.
- **모델보다 데이터 품질을 먼저 봐야 했습니다.** 코퍼스의 9%(57건)가 본문 없는 문서였고,
  이것이 검색 지표를 왜곡하고 있었습니다.
- **기본 설정을 점검해야 했습니다.** 형태소 분석기에 품사 필터를 달지 않아 조사와 어미가
  전부 검색어가 되고 있었습니다. "~할 수 있는지 알려줘"라는 질문에서 점수의 대부분이
  '줘', '는지' 같은 어미에서 나왔고, 정작 핵심어의 기여는 0이었습니다.
  필터를 달자 제목 단어 없는 질문의 MRR이 0.490에서 0.512로 올랐습니다.
