## 2. 노트북 열기와 실행

저장된 출력부터 확인한다. VS Code나 Jupyter에서 노트북을 열고 CAP-01 등의 출력 영역을 캡처하면 된다. HTML 출력이 숨겨지면 코드를 검토한 뒤 신뢰한 노트북으로 열거나 직접 재실행한다. 뷰어의 HTML·CSS 지원에 따라 표와 나란히 배치한 패널의 모양이 달라질 수 있다.

다시 실행하려면 별도 Python 환경에서 저장소 루트 기준으로 다음 패키지를 설치하고, 해당 환경을 노트북 커널로 선택한다.

```bash
python -m pip install -r notebooks/requirements-presentation.txt
```

그 뒤 셀을 위에서 아래로 모두 실행한다. 실행 위치는 저장소 루트 또는 그 아래 `notebooks/`여야 한다. Python 3.9 이상을 사용하며 검증에 사용한 직접 의존성 버전은 requirements 파일에 고정했다. 이는 서비스 전체의 의존성 잠금 파일은 아니다.

이 노트북은 외부 API·LLM·ES 검색을 호출하지 않는다. `.env`가 없어도 기본 설정으로 import할 수 있다. `.env`가 있는 환경에서는 프로젝트 설정 모듈이 읽을 수 있지만 인증정보나 설정 전체를 출력하지 않는다. 함수 기본값 변화가 예시를 조용히 바꾸지 않도록 청킹 800/150, RRF K=60, 재조립 3,000자, 검색 이력 1회를 명시했다.

## 4. Langfuse에서 준비할 평가 캡처

실제 화면은 사용자가 접근 가능한 프로젝트에서 촬영한다. 없는 실행·점수 화면을 새로 그려
실제 캡처처럼 사용하지 않는다.

### 어디를 눌러야 하나

평가 캡처는 **세 화면**이면 끝난다. 사이드바에서 헤매지 말고 아래 주소로 바로 간다.

**① 데이터셋 화면 — 가장 중요한 한 장**

```
https://jp.cloud.langfuse.com/project/cmt0xmxjm000vad0djmng1vvn/datasets/cmu3t4sjc001lad0fis9w1y2i
```

사이드바로 가려면 **Datasets → `confluence-rag-qa-36-indexed`**.
여기 **Runs** 탭에 실행이 한 줄씩 쌓여 있고, 줄마다 Item Count와 지표 평균이 붙는다.

> **2026-09-16 이후 촬영할 때 주의.** 채점기를 RAGAS 표준 5종으로 전부 교체했다
> (`faithfulness`, `answer_relevancy`, `context_precision`, `context_recall`,
> `answer_correctness`). 이전 run들(`ey-interview-36-...`)은 삭제된 6종으로 채점된
> 것이라 **같은 표에 올려도 비교가 안 된다.** 새 run은 이름이 `ragas5-`로 시작한다.
> 아직 새 run이 없다면 이 화면은 캡처 대상이 아니다
> ([EVALUATION.md](../EVALUATION.md) 5장).

**② run 상세 — 36문항이 다 채점됐다는 근거**

①의 표에서 run 이름을 클릭한다. 36개 문항이 한 줄씩 나오고 문항마다 5개 점수가 붙는다.
정답 라벨(`ground_truth_snippet`)이 36문항 전부 채워져 있어 **빈 칸이 없는 것이 정상이다.**
빈 칸이 보이면 채점이 실패한 것이므로 콘솔 경고를 함께 확인한다
([EVALUATION.md](../EVALUATION.md) 2.3절, 3.2절).

**③ trace 하나 — 검색에서 생성까지 이어진 그림**

②에서 아무 문항이나 클릭하면 관측 트리가 펼쳐진다.

```
experiment-item-run
├─ experiment-item-task
│  ├─ rag.embedding
│  ├─ rag.search
│  ├─ rag.context_build
│  └─ rag.generation
└─ experiment-item-evaluation
   └─ RAGAS 지표 5종 → 점수 5개
```

**"검색 → 컨텍스트 → 생성이 한 요청 안에서 이어진다"를 보여주는 화면이 이거다.**
계측(`stage()`)이 실서비스와 같은 코드라서 실서비스 trace와 모양이 같다.

> 이름이 **Langfuse**다. LangGraph는 전혀 다른 도구이므로 검색할 때 섞지 않는다.

### LF-01: 평가 실행과 점수

①에서 다음이 한 화면에 들어오게 캡처한다.

- 데이터셋·실행 이름과 실행 시점
- 지표 이름과 평균 점수
- Item Count(36)

수치는 [EVALUATION.md](../EVALUATION.md) 5절이 기준이다. **여기에 옮겨 적지 않는다.**
두 곳에 적으면 한쪽만 갱신됐을 때 어느 쪽이 맞는지 알 수 없다.

실제 캡처 값이 문서와 다르면 **화면을 편집하지 않는다.** 다른 실행인지 먼저 확인하고,
다른 실행이면 그 실행의 조건을 함께 소개한다.

**중요:** BM25 / kNN / RRF 결합 방식 비교는 Langfuse Experiment가 아니라
`retrieval_fusion_comparison.py`로 따로 측정한 것이다([EVAL_RESULTS_20260916.md](../EVAL_RESULTS_20260916.md)).
Langfuse에는 그 비교 실행이 없다. **①의 화면을 결합 방식 비교 근거로 쓰면 안 된다.**
①은 "평가를 재현 가능하게 관리하고 있다"와 "검색·생성 품질을 같은 실험에서 본다"의 근거다.

### LF-02: 문항 하나를 열어본 사례

②에서 문항 하나를 고른다. 질문, 생성 답변, 기대 답변, 개별 점수가 함께 읽히는 것을 고른다.
성공 사례도 낮은 점수를 검토하는 사례도 가능하다. **문항 하나가 전체 품질을 대표한다고
설명하지 않는다.**

**#34**(`qa36-034`, "제휴병원 할인 혜택 안내문 파일로 받을 수 있어?")가 열어 보기 좋은
문항이다. 첨부파일명이 컨텍스트에 들어가느냐로 답변이 갈렸던 사례다.

> 이 문항의 수정 전/후를 **점수로** 보여주던 근거(`answer_correctness` 0.00 → 0.80)는
> 삭제된 자체 채점기의 값이라 더 이상 인용하지 않는다
> ([EVALUATION.md](../EVALUATION.md) 0장·5.2절). 답변 텍스트 자체의 변화는 두 run의
> 같은 문항을 열면 그대로 보이므로, 점수 대신 **답변을 나란히** 보여준다.

③의 소요 시간은 실행 과정의 근거다. **지연 화면만으로 답변 정확도나 검색 품질을
입증한다고 말하지 않는다.** trace 캡처를 추가한다면 6장의 관측 설명이나 보조 자료에 둔다.

### 외부 발표 전 가릴 정보

회사·고객·직원 실명, 비공개 문서 제목·본문, 내부 URL, 이메일, 프로젝트 식별정보, 인증정보가
보이지 않는지 확인한다. 특히 ③의 `rag.search` / `rag.context_build`는 **Confluence 본문이
그대로 펼쳐지므로** 반드시 확인한다. 공개 권한이 불분명하면 해당 사례 대신 ①의 점수 요약
화면을 사용한다. 마스킹 후에도 지표 이름·측정 조건·점수는 읽을 수 있어야 한다.

## 6. Grafana 운영 관측 캡처 (발표 6페이지)

실측 데이터가 쌓인 상태에서 캡처한다. 데이터가 없으면 `rate(...[5m])` 패널이 전부 빈다.

**캡처 전 실행**

```bash
# 1) 서비스와 모니터링 스택이 떠 있는지
docker ps --format '{{.Names}}\t{{.Status}}' | grep rag-
curl -s http://localhost:9090/api/v1/targets?state=any | grep -o '"health":"[a-z]*"' | sort | uniq -c

# 2) 실서비스 경로로 트래픽 투입 (평가셋 36문항 재사용, 약 2분)
python3 scripts/generate_observability_traffic.py          # 단일 턴 36건
python3 scripts/generate_observability_traffic.py --multiturn   # 멀티턴 5대화 13턴
```

**Grafana 설정** — `http://localhost:3000` (admin/admin) → 폴더 `Confluence RAG`.
시간 범위는 **Last 15 minutes**, 새로고침 30s. 기본값 1시간으로 두면 2분짜리 구간이
한 점으로 뭉쳐 보인다.

| ID | 대시보드 / 화면 | 무엇이 보여야 하는가 |
|---|---|---|
