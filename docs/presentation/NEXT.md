## 지금 멈춘 지점: Python 3.13 환경 준비

서버는 Rocky Linux 9.6이며 기본 Python은 3.9였다. 사용자가 VS Code Remote SSH에서 노트북용 3.13을 원해 아래 명령을 안내했다. **사용자가 실제 실행했는지는 미확인**이다. 다음 작업 때 먼저 설치·가상환경 유무부터 확인하고, 이미 있으면 다시 만들지 않는다.

서버 기본 Python을 교체하지 않고 별도 환경으로 설치한다. 이 명령은 Windows PowerShell이 아니라 SSH로 연결된 서버 터미널에서 실행한다.

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
source "$HOME/.local/bin/env"
uv python install 3.13
cd /confluence-kg-chatbot
uv venv --python 3.13 .venv-presentation
uv pip install --python .venv-presentation/bin/python \
  -r notebooks/requirements-presentation.txt
.venv-presentation/bin/python -m ipykernel install --user \
  --name presentation-313 \
  --display-name "Python 3.13 (발표)"
.venv-presentation/bin/python --version
```

그 뒤 VS Code 노트북에서 `Python 3.13 (발표)` 커널을 선택한다. **3.13에서 패키지 설치·노트북 전체 실행 검증은 아직 하지 않았다.** 가상환경 파일은 커밋하지 않는다.

### 제목과 발표 관점

기존 표지 ‘사내 문서에서 답변의 근거를 찾는 RAG’는 기술 문서처럼 보인다. 제안한 제목은 다음과 같다.

- 제목: **사내 지식 검색을 위한 RAG 챗봇 개발**
- 부제: **Confluence 문서 구조화와 하이브리드 검색 성능 검증**
- 상단: **EY 컨설팅부문 데이터분석 인턴 | 프로젝트 발표**
- 이름은 사용자가 제공한 경우에만 넣고, 화면의 ‘10분’ 표기는 삭제.

### 제안한 본문 장표 제목

| 장 | 제목 |
|---|---|
| 1 | 사내 지식 검색을 위한 RAG 챗봇 개발 |
| 2 | 프로젝트 목표와 시스템 구성 |
| 3 | 비정형 문서 구조화: 병합 표 파싱과 청킹 |
| 4 | 검색 설계: 키워드·의미 검색 결합과 문맥 재조립 |
| 5 | 성능 검증: 질문 표현에 따른 검색 방식 비교 |
| 6 | 서비스 구현: 문서 갱신·멀티턴·모델 라우팅 |
| 7 | 주요 기여와 직무 연관성 |

### 내용 수정 요지

- 2장: 목표 한 문장 + 데이터 준비/질문 처리 흐름. PostgreSQL·Redis는 ‘답변·출처’ 박스가 아니라 별도의 대화 저장 영역에 배치.
- 3장: 원본 병합 표와 실제 파서 출력을 크게. 청킹 캡처는 보조. 문장 설명보다 직접 작성한 로직의 변환 결과를 보여준다.
- 4장: BM25+kNN, RRF, 문맥 재조립 각각의 선택 이유. 후보 청크 각 50개와 최종 서로 다른 문서 최대 5개를 구분. 세부 길이 제한 설명은 발표 노트로.
- 5장: 가장 중요한 분석 사례. ‘Paraphrase 질문’을 ‘표현을 바꾼 질문’으로 쉽게 표기. MRR +0.170은 정확도 17% 향상이 아니다. 해당 평가셋 기준임을 유지.
- 6장: 문서 갱신·멀티턴·모델/관측 세 묶음. 측정하지 않은 비용 절감률이나 멀티턴 평가 성과를 추가하지 않는다.
- 7장: 데이터 처리 → 결과 해석 → 직무 연결. 추상적 다짐과 개인 기여의 과장·축소를 피한다.
- 주의사항을 본문에 너무 많이 나열하지 않는다. 측정 조건과 시연 표기는 남기되 상세 한계는 발표 노트·보조 자료로 옮긴다.
