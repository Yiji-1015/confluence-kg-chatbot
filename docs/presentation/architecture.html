Confluence RAG Chatbot

사내 문서 질의응답 시스템 구조

Confluence 문서를 Elasticsearch에 색인하고, BM25 키워드 검색과 벡터 검색을 RRF로 결합한 결과를 근거로 답변합니다. 아래 수치는 모두 현재 실행 중인 설정과 색인에서 읽은 값입니다.

서비스 구성

질문 하나가 지나가는 길

  1. 01 모델 라우팅 질문이 12자 미만이거나 이력 포함 1000자 이상이면 gpt-4o, 그 외에는 deepseek-chat.
  2. 02 검색 질의 구성 최근 1턴을 반영해 검색어만 다시 만든다. 답변 생성에는 원본 질문을 그대로 쓴다.
  3. 03 질문 임베딩 text-embedding-3-small로 1536차원 벡터를 만든다.
  4. 04 하이브리드 검색 BM25(제목 2.0배)와 kNN이 각각 50청크를 가져오고, 순위만 쓰는 RRF(K=60)로 합친 뒤 최신성 가산점을 얹어 문서 5개를 고른다.
  5. 05 컨텍스트 조립 고른 문서의 청크를 다시 이어 붙인다. 문서당 최대 3000자.
  6. 06 답변 생성 LiteLLM을 거쳐 라우팅된 모델을 호출하고, 답변과 출처 문서를 함께 돌려준다.

검색 설정

운영 중인 값. 재색인 없이 환경 변수로 바꾼다.
항목값왜 이 값인가
RRF_K60점수가 아니라 순위로 합치므로 BM25와 kNN의 스케일을 맞출 필요가 없다
RETRIEVAL_CANDIDATE_SIZE50후보 풀이 좁으면 한쪽에만 든 청크가 0점 취급돼 하위권과 구분되지 않는다
RETRIEVAL_TOP_K5컨텍스트에 넣을 서로 다른 문서 수
DOC_CONTEXT_MAX_CHARS3,000문서 하나가 컨텍스트를 독점하지 않게 자른다
RECENCY_BOOST_MAX0.04RRF 최고점의 일부만 얹는다. 절대값을 그대로 더하면 가산점이 순위를 뒤집는다
SEARCH_HISTORY_TURNS1검색어에 반영할 직전 대화 턴 수
