## 2. 표 ① 검색 방식 비교

### 2-1. v2 / v4 (38문항, 정답 문서 38종)

| 방식 | v2 원본 hit@5 / MRR | v4 표현 바꿈 hit@5 / MRR |
|---|---|---|
| **하이브리드 RRF (운영)** | 0.974 / 0.890 | **0.711 / 0.525** |
| 이전 방식 min-max 4:6 | 0.974 / **0.895** | 0.632 / 0.501 |
| BM25 단독 | 0.947 / 0.864 | 0.605 / **0.390** |
| kNN 단독 | 0.895 / 0.786 | 0.605 / 0.496 |

**원본 질문에서는 네 방식이 갈리지 않는다.** 질문의 84.7%가 문서 제목 단어를 그대로 갖고
있어 BM25만으로도 충분하다. 이 표만 보면 하이브리드를 쓸 이유가 없어 보인다.

**표현을 바꾸면 갈린다.** BM25 MRR이 0.864 → 0.390(**−55%**)로 무너지고, 하이브리드는
0.890 → 0.525(−41%)로 버틴다.

### 2-2. 평가셋 C (33문항)

| 방식 | hit@5 | MRR |
|---|---|---|
| **RRF (운영)** | **0.818** | 0.553 |

| BM25 단독 | 0.697 | **0.563** |

`hit@5`는 RRF가 가장 높지만 `MRR`은 BM25 단독이 근소하게 앞선다. 33문항 기준 1문항 차이라

## 4. 표 ③ RRF가 실제로 바꾼 문항

### 4-1. v2 / v4

| | v2 원본 | v4 표현 바꿈 |
|---|---|---|
| RRF만 찾음 | 0 | **3** |
| RRF만 놓침 | 0 | **0** |
| 순위 상승 | 1 | 2 |
| 순위 하락 | 2 | 3 |
| 둘 다 실패 | 1 | 11 |

**원본에서는 RRF가 1문항 손해다**(상승 1 / 하락 2). min-max MRR이 0.895로 근소하게 높았던
이유가 이것이다. **표현을 바꾸면 min-max가 top5에 넣지 못한 3건을 RRF가 찾아내고,
반대 방향은 0건이다.**

```
"어떤 문서에 2025년 말에 진행할 AI 모델 관련 테스트 계획이 있던데..."   min-max 실패 -> RRF 1위
"작년 12월 중순에 있었던 두 번째 기술 회의에서 파일 관련해서..."        min-max 실패 -> RRF 2위
"기획 관련 자료에서 제안서 양식의 핵심적인 특징이 뭐야?"                min-max 실패 -> RRF 5위
```

세 질문 모두 문서 제목 단어가 없다. BM25 점수가 바닥이라 min-max에서는 정규화해도 kNN
점수에 눌려 사라지지만, RRF는 점수가 아니라 **순위**만 쓰므로 "kNN 리스트 3위" 같은 기여가
살아남는다.

### 4-2. 평가셋 C (33문항)

RRF만 찾음 **5건** / RRF만 놓침 **1건** / 상승 5 / 하락 4 / 둘 다 실패 5.
순증 4문항이 `hit@5` 0.697 → 0.818의 실체다.

### 4-3. 둘 다 실패한 문항의 성격

v4의 실패 11건은 검색 방식 문제가 아니다.

```
"최근에 있었던 전체 팀 회의에서 어떤 결정이 내려졌는지"
"올해 세 번째 분기 모임에서 최고 경영자가 어떤 얘기를"
"2026년 3월 첫째 주에 있었던 우리 팀 회의에서"
```

**질문이 상대적 시점으로만 문서를 지칭한다.** 회의록이 수십 건이라 어느 것인지 특정되지
않는다. `qa-v2-021`이 남은 실패인 것과 같은 원인이며, 한 문항에 맞춰 전역 스코어링을
바꾸는 것은 과적합이라 유지한다.

## 5. Nori 분석기 개선 A/B

개선 전 설정으로 별도 인덱스(`confluence-oldnori-ab`)를 만들어 비교했다. `_reindex`는
`text_vector`를 그대로 복사하고 `text`만 대상 인덱스의 분석기로 재분석하므로 임베딩 비용이
들지 않는다 (3,493건 / 실패 0).

| | 개선 전 | 현재 |
|---|---|---|
| tokenizer | `nori_tokenizer` (decompound 기본=discard) | `ko_nori_tokenizer` (decompound=**mixed**) |
| filter | 없음 | `ko_pos_filter` + `lowercase` |

```
HashiCorp 자격증   개선 전 ['HashiCorp','자격','증']  ->  현재 ['hashicorp','자격증','자격','증']
BlackBird         개선 전 ['BlackBird']            ->  현재 ['blackbird']
```

### 결과 — 효과가 v4에서만 나타난다

| 평가셋 | 지표 | 개선 전 | 현재 |
|---|---|---|---|
| **v2 원본** | BM25 hit@5 / MRR | **0.974 / 0.921** | 0.947 / 0.864 |
| | 하이브리드 hit@5 / MRR | **0.974 / 0.921** | 0.974 / 0.890 |
| **v4 표현 바꿈** | BM25 hit@5 / MRR | 0.474 / 0.316 | **0.605 / 0.390** |
| | 하이브리드 hit@5 / MRR | 0.684 / 0.502 | **0.711 / 0.525** |
| **평가셋 C** | BM25 hit@5 / MRR | 0.727 / 0.557 | 0.697 / 0.563 |
| | 하이브리드 hit@5 / MRR | 0.788 / 0.575 | **0.818** / 0.553 |

**v2에서는 손해다.** BM25 순위 변동 3건이 전부 악화다. 제목 단어가 그대로 있는 질문에서는
원형 토큰이 오히려 유리하기 때문이다.

**v4에서는 분명한 이득이다.** BM25 `hit@5`가 0.474 → **0.605**(+0.131), 순위 변동 15건 중
**개선 11 / 악화 4**다. 코드 주석이 근거로 든 `BlackBird` 사례가 실제로 확인된다.

```
0위(실패) -> 1위 | 우리 회사에서 사용하는 BlackBird 서버의 IP 주소랑...
0위(실패) -> 2위 | 기획 관련 자료에서 제안서 양식의 핵심적인 특징이 뭐야?
    3위 -> 2위 | OCR API가 사용하는 포트 번호가 뭐야?
```

**RRF와 같은 패턴이다.** 두 개선 모두 제목 단어가 누출된 질문에서는 효과가 없거나 손해이고,
표현을 바꾼 질문에서 값어치가 드러난다. **발표에서 Nori를 다루려면 v4 대비를 반드시 함께
보여야 한다.** v2 수치만 제시하면 개선이 아니라 퇴보로 읽힌다.

## 6. 운영 지표 (실서비스 경로 측정)

`run_qa.py`는 `search_hybrid` / `generate_answer`를 직접 호출해 API를 우회하므로 Prometheus에
아무것도 남지 않는다. 단계별 계측(`stage()`)이 `api/v1/chat.py`에만 있기 때문이다.

이번에는 Spring Boot가 호출하는 것과 같은 경로(`POST /internal/chat`)로 52문항을 실행했다.
실행 직전·직후의 `/metrics`를 떠서 **이번 실행분만** 분리했다.

**성공 52 / 실패 0 / 총 159.3초**

| 단계 | 건수 | 평균 |
|---|---|---|
| `embedding` | 52 | 0.376s |
| `search` | 52 | 0.098s |
| `context_build` | 52 | ~0.000s |
| `generation` | 52 | **2.585s** |
| 전체 요청 | 52 | 3.06s (p95 5.32s) |

**생성이 전체 지연의 84%다.** 검색은 0.1초로 병목이 아니다.

> p50/p95는 히스토그램 버킷 경계(0.05·0.1·0.25·0.5·1·2·5·10·20·30·60)로 반올림되므로
> 정밀하지 않다. **평균을 기준 수치로 쓴다.**

## 7. 정리

- **RRF도 Nori 개선도, 제목 단어가 누출된 질문에서는 효과가 보이지 않는다.**
  표현을 바꾼 질문에서만 값어치가 드러난다. 이것이 v4 평가셋을 만든 이유이자 발표의 핵심이다.
- 구어체 질문에서 BM25 단독이 가장 약하고(0.50) 하이브리드가 가장 강하다(0.83).
- 남은 실패는 대부분 검색 방식이 아니라 **질문이 문서를 특정하지 못하는 문제**다.
- 생성이 지연의 84%이며 검색은 병목이 아니다.
