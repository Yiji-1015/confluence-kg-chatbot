## 1. 오늘 진행한 핵심 작업

### 1-1. 포트폴리오 관점 아키텍처 재정립
- **목표**: 단순 도구 나열을 지양하고, **제한된 자원(PoC/개인 개발 환경)에서 실무적으로 필요한 컴포넌트를 선별하고 단계적으로 확장 가능한 계층형 아키텍처(Modular Layered Architecture)**를 설계하고 문서화.
- **핵심 메시지**:
  - 도구의 존재 이유와 트레이드오프 정의 (왜 필요한가? 언제 배제 가능한가?)
  - 상시 필수 구동(Core/App)과 선택적 구동(Search/KG/Obs) 분리
  - Polyglot Persistence, Dynamic Routing & Fallback, OTel 관측성 등의 실무형 운영 설계 부각

### 1-2. 계층별 Docker Compose 파일 분리
기존의 무거운 단일 `docker-compose.yml`을 5개의 목적별 파일로 분리하고 공통 네트워크(`confluence-net`)로 연결:
1. `docker-compose.yml`: **[Core Layer]** PostgreSQL 16 (영구 저장) + Redis 7 (세션 캐시) 및 공통 브리지 네트워크 선언 (~1GB RAM)
2. `docker-compose.app.yml`: **[App Layer]** Spring Boot 백엔드 + FastAPI AI 엔진 컨테이너화 (~1.5GB RAM)
3. `docker-compose.search.yml`: **[Search Layer]** Elasticsearch 8.15(Nori 형태소 분석기 + Dense Vector) + Kibana UI + Setup (~3GB RAM)
4. `docker-compose.kg.yml`: **[KG Layer]** Neo4j 5 Community 지식 그래프 DB (~2GB RAM)
5. `docker-compose.obs.yml`: **[Observability/Gateway Layer]** LiteLLM 라우팅 게이트웨이 (~0.8GB RAM)

### 1-3. FastAPI AI 엔진 컨테이너화 및 Langfuse 안전성 확보
- `ai-server/Dockerfile`: Python 3.12-slim 기반 경량 멀티스테이지 컨테이너 이미지 빌드 및 `/internal/health` 헬스체크 설정

### 1-5. 실제 사람 질의 양상(Human-like Query Pattern) 대응 및 실시간 공유 환경 구축
- **합성 데이터셋 vs 실제 사용자 질의 괴리 분석**:
  - LLM 합성 벤치마크는 정제된 문장형이지만, 실제 사내 직원은 `"휴가어케씀"`, `"블랙버드 ip"` 등 거친 단문/구어체/오타 위주로 질문함을 식별
- **사외/모바일 실시간 공유 환경 구성**:
  - Cloudflare Tunnel(`cloudflared`)을 통해 로컬 개발 환경(`localhost:8080`)을 외부 사용자/모바일로 안전하게 실시간 공유
  - 브라우저 `localStorage` 기반 고유 `userId`(UUID) 발급으로 여러 사용자가 동시 접속해도 개별 대화 세션이 완벽하게 격리됨을 검증

### 1-6. 사내 Confluence 579개 문서 로컬 대량 색인(Ingestion) 완료
- 신규 Docker 환경의 빈 Elasticsearch 클러스터에 전체 색인 파이프라인(`scripts.ingest`) 실행
- **579개 문서 ➔ 2,575개 청크**로 파싱 및 1536차원 벡터 임베딩 생성 후 Elasticsearch(Nori 한국어 분석기 + Dense Vector)에 대량 색인 완료
- `updated_at` date 포맷 안전 처리 및 대용량 bulk 색인 안정성 강화

### 1-7. 웹 UI 고도화 (마크다운 렌더링 + 타이핑 스트리밍 + UI 정제)
- `backend/src/main/resources/static/index.html`:
  - **마크다운 서식 렌더링**: `marked.js` + `DOMPurify` 도입으로 `**볼드체**`, `1. 2. 3. 번호 목록`, `테이블(표)`, `코드 블록` 완벽 렌더링
  - **Typewriter Streaming**: 답변 생성 후 부드럽게 한 글자씩 타이핑되는 효과를 적용하여 사용자 체감 대기 시간 단축
  - **원클릭 복사 버튼**: 봇 답변 말풍선 호버 시 [복사] 버튼 제공
  - **UI 정제**: 개발자용 정적 배지("Redis + JPA 연동됨" 등)를 제거하고 상용 SaaS 수준의 미니멀한 프로덕션 UI로 개편

### 1-8. 콜드 스타트(Cold Start) 제거를 위한 서버 자동 Warmup(예열) 구현
- **문제점**: 서버 최초 기동 시 LiteLLM과의 TLS 핸드셰이크 및 Elasticsearch 인덱스 캐시 미워밍으로 인해 '첫 번째 질문'의 지연(10초 이상) 발생
- **해결책 (`ai-server/app/main.py`)**:
  - FastAPI 최신 표준 `@asynccontextmanager` `lifespan` 관리자 구현
  - 서버 부팅 시 백그라운드에서 `embed_texts_async(["warmup"])`과 `search_hybrid_async("warmup", ...)`을 1회 조용히 실행
  - DB/세션 오염 없이 LiteLLM TLS 소켓과 Elasticsearch 쿼리 캐시를 100% 예열 완료

### 1-9. PostgreSQL 실시간 대화 이력 영구 적재 검증
- 실제 사용자가 Cloudflare/로컬을 통해 나눈 질문(`"휴가를쓰고싶은데.."`, `"집 가고싶음"`)과 AI 답변, Confluence 출처 URL이 `chat_messages` 테이블에 실시간으로 완벽하게 저장됨을 직접 쿼리로 검증

## 2. 주요 Q&A 및 설계 결정

### Q1. "Compose 파일을 분리하면 컨테이너 간 통신은 어떻게 되는가?"
- 모든 Compose 파일에 `networks: default: name: confluence-net`을 정의하여, 독립 실행하든 `-f` 옵션으로 조합 실행하든 동일한 `confluence-net` 브리지 네트워크에 조인됨.
- 따라서 `postgres`, `redis`, `elasticsearch`, `litellm`, `neo4j` 호스트명으로 컨테이너 간 완벽한 통신이 보장됨.

### Q2. "점수 정규화와 재랭킹(Re-ranking)은 어떻게 동작하며 가중치 비율은?"
- BM25 원시 점수와 kNN 코사인 점수를 각각 0~1로 Min-Max 정규화한 후, $\text{BM25}: 3.0(30\%), \text{kNN}: 7.0(70\%)$ 가중합으로 청크 순위를 재정렬.
- 고유명사 키워드는 `title^2.0`(제목 2배 가중치)로 보강하고, 사내 직원들의 거친 구어체/의미 기반 질문은 의미 벡터(70%)가 잡아내도록 밸런싱.
- 상위 40개 후보군 탐색 ➔ 정밀 재랭킹 ➔ Top-3 서로 다른 문서 선별 ➔ `_fetch_full_doc_text`로 문서 전체 청크 맥락(최대 12,000자)을 조립해 LLM에 전달.

### Q3. "Warmup 코드는 사용자가 브라우저를 켤 때마다 도는 것인가?"
- 아님. **서버가 부팅될 때 딱 1번만** 백그라운드에서 실행됨.
- 사용자는 이미 200도로 예열된 서버에 입장하여 첫 질문부터 지연 없이 고속 처리받게 됨. (DB나 세션 기록에는 0.001%도 남지 않음)
