# 2026-08-26 작업일지 — Knowledge Graph 평가 데이터셋

## 1. Person/Document 관계 평가 데이터셋 구축

- Elasticsearch의 문서 메타데이터(`doc_id`, `title`, `author`, `primary_contributor`, `links`, `path`)를 기반으로 Knowledge Graph 평가용 스냅샷 생성기를 작성했다.
- 생성 파일:
  - `ai-server/evaluation/generate_person_dataset.py`
  - `ai-server/evaluation/person_dataset_items.py`
- 데이터셋 ID 형식은 `qa-v3-person-001`부터 시작하며 총 20문항이다.
- 관계 유형:
  - `AUTHORED`: 최초 작성자와 문서의 관계
  - `TOP_CONTRIBUTOR`: 최다 기여자와 문서의 관계
  - `LINKS_TO`: Confluence 문서 간 링크 관계
- 문항 구성:
  - 최초 작성자와 최다 기여자 비교: 8문항
  - 연결된 두 문서의 작성자·최다 기여자 조회: 8문항
  - 연결된 문서 사이의 인물 동일 여부 비교: 4문항
- 각 문항에 `expected_doc_ids`, `expected_entity_ids`, `expected_relations`, `expected_path`, `source_titles`, `snapshot_at` 메타데이터를 포함했다.
- 민감할 가능성이 있는 문서와 유효하지 않은 사용자 값은 생성 대상에서 제외한다.
- `TOP_CONTRIBUTOR`는 재색인 후 바뀔 수 있으므로 데이터셋을 스냅샷으로 관리하고 재생성 시각을 기록한다.

## 2. 인코딩 확인

- PowerShell `Get-Content`에서 한글이 깨져 보여 파일 손상으로 의심했으나, BOM 없는 UTF-8 파일을 PowerShell이 잘못 해석한 표시 문제였다.
- 실제 파일의 UTF-8 내용과 생성된 질문·답변은 정상이며, Unicode replacement character도 없음을 확인했다.

## 4. Phase 5 Knowledge Graph (GraphRAG) 구축 및 벤치마크 검증

### 4-1. Neo4j 클라이언트 및 스키마 모듈 구현
- `ai-server/app/kg/neo4j_client.py`:
  - `init_kg_schema()`: `Person.name` (UNIQUE), `Document.doc_id` (UNIQUE), `Category.name` (UNIQUE), `Document.title` (INDEX) 제약조건/인덱스 생성.
  - `ingest_graph_data()`: Confluence 514개 문서 메타데이터로부터 `Person`, `Document`, `Category` 노드 및 `[:AUTHORED]`, `[:TOP_CONTRIBUTOR]`, `[:LINKS_TO]`, `[:BELONGS_TO]` 관계 Cypher UNWIND 배치 일괄 적재.
  - `search_graph_context()` / `search_graph_context_async()`: 질문 내 인물/문서 식별 및 Hybrid Search 결과 문서 ID 기반 1~2 hop 서브그래프 Cypher 탐색 및 RAG Prompt Context 포맷팅.

### 4-2. 대량 그래프 색인 스크립트 작성 및 실행
- `ai-server/scripts/ingest_kg.py`:
  - ES에서 514개 고유 Confluence 문서 메타데이터를 추출해 Neo4j에 일괄 적재 완료.
  - 적재 결과:
    - `Document` 노드: 514개
    - `Person` 노드: 34명
    - `Category` 노드: 14개
    - `[:AUTHORED]` 관계: 514건
    - `[:TOP_CONTRIBUTOR]` 관계: 514건
    - `[:LINKS_TO]` 관계: 28건
    - `[:BELONGS_TO]` 관계: 514건

### 4-3. FastAPI 메인 RAG 파이프라인 결합
- `ai-server/app/api/v1/chat.py`:
  - Hybrid Search(BM25 + kNN)와 함께 `search_graph_context_async`를 실행하여 1~2 hop 관계 맥락을 LLM 프롬프트 상단에 주입.
  - 응답 스키마 `ChatResponse.graphContext`에 노드/엣지 엔티티 반환.
- `ai-server/app/main.py`:
  - Lifespan Warmup에 Neo4j 커넥션 풀 예열 추가 및 graceful shutdown 드라이버 종료 적용.

### 4-4. 20문항 관계형 벤치마크 평가 결과 (run_kg_eval.py)
- `ai-server/evaluation/run_kg_eval.py`:
  - Baseline (Hybrid Only) vs Proposed (Hybrid + Neo4j GraphRAG) 비교 평가:
    - **Entity Hit Rate**: Baseline `1.2%` ➔ **Proposed `76.7%` (+75.4%p)**
    - **Relation Hit Rate**: Baseline `0.0%` ➔ **Proposed `93.3%` (+93.3%p)**
    - **평균 Latency**: Baseline `2,993ms` vs Proposed `2,467ms` (그래프 맥락 주입으로 LLM의 불필요한 탐색/망설임 감소)
