## 1. 오늘 진행한 핵심 작업

### 1-1. Spring Boot 백엔드 (`backend/`) 계층형 아키텍처 완성
- **[1] Entity**: `ChatSession` (대화방 UUID, 제목, 생성일), `ChatMessage` (발화자, 내용, 출처 JSON, 생성일)
- **[2] Repository**: `ChatSessionRepository`, `ChatMessageRepository` (Spring Data JPA)
- **[3] DTO**: `ChatRequestDto` (유효성 검증 `@NotBlank`), `ChatResponseDto`, `SourceDocumentDto`, `ChatSessionDto`, `ChatMessageDto`, `InternalChatDto`
- **[4] Mapper**: `ChatMapper` (Entity ↔ DTO 변환 및 Jackson 출처 직렬화)
- **[5] Config**:
  - `RedisConfig`: JSON 직렬화용 `RedisTemplate<String, String>`
  - `AiClientConfig`: Python AI Engine 통신용 최신 내장 `RestClient` (60초 타임아웃)
- **[6] Service**:
  - `RedisSessionService`: 최근 5턴 대화 캐싱 (슬라이딩 윈도우) 및 30분 TTL 자동 만료 (Sliding Expiration)
  - `AiEngineClient`: Python AI Engine(`http://localhost:8000/internal/chat`) 호출 및 장애 시 Fallback 처리
  - `ChatService`: 세션 발급/관리 ➔ Redis 멀티턴 맥락 조회 ➔ AI 호출 ➔ Redis & JPA 동시 영속화
- **[7] Controller**: `ChatController` (`POST /api/chat`, `GET /api/sessions`, `GET /api/sessions/{id}/messages`, `DELETE /api/sessions/{id}`)

- JPA `ddl-auto: update`로 엔티티 기반 테이블 자동 생성 검증.

## 2. 주요 개념 및 아키텍처 Q&A

### Q1. "application.yaml과 docker-compose.yml은 같이 가는 건가?"
- **정확히 맞음**: `docker-compose.yml`은 "인프라를 어떤 포트/비번으로 띄울지", `application.yaml`은 "Spring Boot가 그 띄워진 인프라에 어떻게 찾아가 접속할지" 1:1로 짝을 이룸.

### Q2. "WebClient(WebFlux)가 꼭 필요한가?"
- Spring Boot 3.2+ 최신 표준인 **`RestClient`**를 사용하면 무거운 `webflux` 라이브러리 없이 Spring Boot Web 기본 내장 기능만으로 가볍고 직관적인 동기식 통신 가능.

### Q3. "세션은 Redis에 넣는다면서 왜 JPA ChatSession 엔티티가 또 필요한가?"
- **Redis 세션 (단기 기억)**: *지금 나누는 최근 5턴 대화 맥락*을 0.5ms 만에 AI에게 넘겨주기 위함 (30분 후 자동 삭제).
- **PostgreSQL JPA 세션 (영구 장부)**: 사용자가 며칠 뒤에 와도 좌측 사이드바의 **"과거 대화 목록"을 클릭해 다시 볼 수 있게 하기 위함** (영구 보관).
- ➔ 실무 표준인 **Polyglot Persistence(Redis + RDB)** 구조.

### Q4. "답변이 이상하게 나올 때는 어디를 봐야 하는가?"
- **1순위 (80%) 검색 실패**: `search_hybrid()` 결과에 정답 문서가 없는지 확인 ➔ 형태소 분석기/가중치/청크 크기 튜닝.
- **2순위 생성 실패**: 문서는 잘 찾았는데 LLM이 헛소리할 때 ➔ 시스템 프롬프트 튜닝.
- **3순위 멀티턴 오해**: 앞선 대명사를 잘못 재작성할 때 ➔ Query Rewrite 프롬프트 튜닝.
- *(메모: PostgreSQL DB 뷰어로 나중에 DBeaver 쓸 예정)*

### Q5. "문서 색인 임베딩과 질문 임베딩의 차원 수가 달라도 검색이 가능한가?"
- **절대 불가능 (수학적 불가)**: 두 벡터 간의 내적(Dot Product)/코사인 유사도를 계산하려면 차원 수가 100% 동일해야 함.
- 우리 시스템은 문서 색인과 질문 검색 모두 **OpenAI text-embedding-3-small (1536차원)**으로 완벽히 통일되어 있음.
